# 项目白皮书：业务目标与价值愿景

## 1. 文件定位

本文档定义本项目的长期愿景、价值目标、业务范围、价值度量体系、全生命周期管理范围和建设原则。

本文档不是详细需求规格说明，不维护实现状态，不维护需求跟踪表。项目级与模块级可验收需求、实现证据、测试结果和差距，仍以 `ai_shared/requirements/` 下的正式需求文件为准。

本文档也不是单纯的软件架构说明。软件架构、数据平台、微服务、Web 工作台、AI、数字孪生和自动化能力都是达成项目价值目标的手段。本项目的根本目标是：在并网风光储电厂资产全生命周期内，以可计算、可执行、可验证的方式持续提升资产价值，实现资产效益最大化。

## 2. 项目愿景

本项目面向并网风光储电厂及其相关设备、系统、模型和运行过程，建设一套以资产价值最大化为导向的智能化管理平台。

平台将风电、光伏、储能、并网点、测风塔、激光雷达、第三方系统、仿真模型、机器学习模型、运维活动和控制策略统一纳入数据闭环与决策闭环之中。通过数据底座、能力服务、应用编排、统一工作台、治理审计和运维观测等组件，将分散的生产数据、运行经验、模型知识和管理动作转化为可复用的资产管理能力。

项目追求的不是“做一个大数据平台”本身，而是以数据闭环、AI 和数字孪生为核心手段，支撑产品、设备与电站资产的全生命周期管理，持续提升资产在安全、合规、可靠、经济和可持续约束下的综合价值。

## 3. 顶层价值目标

### 3.1 资产效益最大化

本项目将并网风光储电厂视作具有长期价值创造能力的资产系统。资产价值不等于短期发电量，也不等于单次控制策略收益，而是资产在全生命周期内，在风险可接受、成本可控、合规满足和设备能力不被透支的前提下，持续交付经营、运行和技术价值的能力。

平台的顶层目标可表述为：

```text
在安全合规边界内，通过数据闭环、AI 与数字孪生持续优化 Performance、Risk、Cost 的平衡关系，
实现产品、设备与电站资产全生命周期价值最大化。
```

其中：

```text
Performance：资产运行绩效、能量交付能力、响应能力、协同控制能力和业务目标达成水平。
Risk：设备、运行、并网、控制、网络安全、数据质量、模型误判和管理过程中的风险暴露。
Cost：为了实现绩效提升所付出的可量化或可追踪代价，包括电量损失、设备寿命消耗、储能损耗、运维资源、人员工时、停机窗口、非计划处置和技术改造代价。
```

项目不把 Performance、Risk、Cost 简化为单一线性公式，也不把某个局部指标作为唯一目标。平台应支持多目标、分层、受约束的价值优化：

```text
目标：提升资产全生命周期净价值
约束：安全、合规、风险承受能力、设备寿命、并网规则、运行边界、数据可信度
手段：感知、建模、预测、诊断、仿真、优化、控制、复盘、持续改进
```

### 3.2 从数据可见到价值闭环

项目能力成熟度应从“看见数据”逐步走向“验证价值”：

```text
数据可见
  -> 状态可知
  -> 风险可识别
  -> 绩效可度量
  -> 成本可归因
  -> 策略可推演
  -> 动作可执行
  -> 结果可验证
  -> 经验可沉淀
  -> 能力可复用
```

只有当系统能证明某项策略、算法、模型、维护行动或控制动作对 Performance、Risk、Cost 的影响，才算真正形成价值闭环。

## 4. 参考框架与方法论基础

本项目的价值体系、管理闭环和技术治理参考以下成熟框架。

### 4.1 资产管理：ISO 55000 / ISO 55001

资产管理体系强调资产价值实现、组织目标对齐、生命周期管理、风险管理和持续改进。项目采用资产管理视角定义平台目标：平台不是单纯的采集、存储或算法系统，而是支撑资产价值实现的数字化基础设施。

落地为：

```text
资产对象统一建模
资产状态持续感知
资产绩效持续度量
资产风险持续评估
资产成本持续归因
资产策略持续优化
资产价值持续验证
```

### 4.2 风险管理：ISO 31000

项目采用风险识别、风险分析、风险评价、风险处置、监控与沟通的闭环思想，把风险作为资产价值优化的约束条件和决策输入，而不是事后异常记录。

风险管理覆盖：

```text
设备可靠性风险
运行约束违规风险
并网与调度合规风险
控制命令风险
数据质量风险
模型误判风险
网络安全风险
配置变更风险
多节点一致性风险
人工处置风险
```

### 4.3 质量改进：PDCA 与 Six Sigma / DMAIC

项目采用 PDCA 作为持续改进的基本闭环：

```text
Plan：定义目标、约束、指标和策略假设
Do：执行采集、分析、仿真、优化、控制或管理动作
Check：比较实际结果与预期目标，评估 PRC 影响
Act：固化有效策略，修正无效假设，更新模型与规则
```

对于复杂问题、质量波动、策略失效和异常根因分析，采用 Six Sigma 的 DMAIC 思路：

```text
Define：定义问题、资产对象、价值目标和边界条件
Measure：建立指标、采集数据、确认基线
Analyze：分析偏差、根因、相关性和约束冲突
Improve：形成优化方案、控制策略、维护措施或模型改进
Control：通过监控、审计、版本和门禁保持改进效果
```

### 4.4 数字孪生：ISO 23247 与 IEC 63278 / AAS

项目采用数字孪生作为资产对象、运行状态、模型、事件、约束和策略的统一表达与推演基础。

数字孪生不是简单三维可视化，也不是静态设备台账，而是围绕资产全生命周期的数字表达、状态同步、模型联动、场景推演和结果验证机制。

数字孪生至少承担五类职责：

```text
资产表达：统一表达场站、设备、测点、模型、部件、拓扑和业务语义
状态映射：持续映射实时状态、历史状态、健康状态和运行边界
行为建模：表达设备行为、控制逻辑、并网约束和运行策略
情景推演：支持方案对比、参数扰动、工况模拟和风险评估
价值评估：量化策略对 Performance、Risk、Cost 的影响
```

### 4.5 AI 治理：ISO/IEC 42001 与 NIST AI RMF

项目采用受控 AI，而不是无边界自动决策。AI 能力必须服务于资产价值目标，并纳入权限、审计、模型版本、数据血缘、效果监控和风险管理。

AI 的主要定位是：

```text
感知增强：从多源数据中识别状态、异常、模式和趋势
诊断增强：辅助故障定位、根因分析和风险归因
预测增强：预测功率、负荷、寿命、故障、健康度和风险暴露
优化增强：提出多约束条件下的候选策略
交互增强：通过 AI Agent 降低复杂分析和跨系统查询的认知成本
```

AI 不直接替代资产所有者、运行人员或管理人员的责任。涉及控制下发、设备设点、安全边界和经济责任的动作，必须经过授权、审计、确认和可回溯验证。

### 4.6 工业网络安全：IEC 62443 与 NIST CSF

本项目涉及生产运行数据、工业控制边界和可能的控制反向下发，因此安全合规是价值实现的前提，而不是附加功能。

平台必须坚持：

```text
安全分区
最小开放面
最小权限
控制链路默认关闭
写入命令强审计
配置变更可追溯
关键链路可恢复
异常行为可检测
```

数据闭环、AI 和数字孪生能力不得破坏现场控制系统边界，不得替代 SCADA、保护、测控、PCS、BMS 等原系统的核心安全职责。

## 5. 价值度量体系

### 5.1 Performance：运行绩效

Performance 用于刻画资产在既定边界条件下的有效运行能力。它不等同于单一发电量或利用小时，而是包括可用性、效率、响应性、指令达成度、稳定性和协同控制效果。

典型指标包括：

```text
可用性 Availability
运行效率 Efficiency
指令达成度 Compliance
功率波动率
爬坡违规率
指令响应时间
指令达成偏差
储能有效协同贡献率
波动削减率
故障恢复后性能恢复速度
多时间尺度 OOE / 运行有效性指标
```

其中 OEE 可作为设备效率评价的参考，但新能源电站运行具有气象、限发、调度、储能 SOC、并网规则和电价机制等外部约束，因此平台应采用面向运行系统的 OOE 或等价指标体系，并保留指标来源、口径、约束条件和聚合规则。

### 5.2 Risk：风险暴露

Risk 用于刻画运行状态、设备状态、控制策略、外部约束和管理过程对资产价值造成损害的可能性及影响。

典型指标包括：

```text
MTBF
MTTR
故障类型分布
可恢复性指数
等效强迫停运风险指数
关键部件健康度风险因子
控制偏差风险指数
运行约束违规率
调度 / 并网不合规事件率
考核暴露风险指数
数据质量风险指数
模型置信度风险
网络安全事件风险
综合风险暴露指数
```

风险不应只在事故发生后统计。平台应支持风险的早期识别、趋势预警、根因分析、风险处置建议和处置效果复盘。

### 5.3 Cost：资产级代价

Cost 用于刻画为了实现绩效提升所付出的资源消耗和长期代价。它不是传统财务成本的简单替代，而是面向技术运行和资产价值的代价表达。

典型指标包括：

```text
限发 / 弃风 / 弃光能量成本
储能转换损耗成本
等效寿命消耗成本
频繁调节代价
非计划处置成本指数
检修窗口占用成本
备件与维护资源占用
人员工时消耗
模型训练与计算资源成本
综合成本指数
```

Cost 不应被孤立优化。低成本但引入高风险的策略、短期高绩效但透支设备寿命的策略，都不应被视为高价值策略。

## 6. 全生命周期管理范围

项目支撑的全生命周期不是单一软件生命周期，而是产品、设备、电站资产和模型能力的综合生命周期。

### 6.1 产品全生命周期

产品全生命周期至少覆盖：

```text
设计
生产
采购
运输
运维
退出
```

各阶段的价值闭环如下：

```text
设计：沉淀运行经验、故障模式、性能边界和成本约束，反哺产品选型、设备规格、控制策略和数字孪生模型。
生产：记录制造批次、关键部件、质量检验、出厂试验和一致性数据，为后续运行差异、可靠性分析和缺陷追溯提供依据。
采购：关联供应商、设备型号、合同条款、质保边界、交付周期和全生命周期成本，支撑资产采购决策和供应商评价。
运输：记录物流路径、环境暴露、冲击振动、交付状态和异常事件，形成安装前风险评估和责任追溯依据。
运维：持续采集运行、故障、维护、检修、技改、控制和能量数据，形成 Performance、Risk、Cost 闭环优化。
退出：支持寿命评估、退役决策、备件复用、残值评估、处置记录和经验回流，避免资产退出阶段价值损失不可追溯。
```

### 6.2 电站资产生命周期

```text
规划建设
并网验收
运行监测
能量管理
风险管理
性能优化
维护决策
经营分析
资产评估
持续改进
```

平台通过 PRC 体系支持设备级、系统级、电站级和集团级资产管理决策。

### 6.3 模型与算法生命周期

```text
数据集定义
特征工程
模型训练
模型评估
模型注册
模型发布
在线推理
效果监控
漂移检测
版本回滚
模型退役
```

AI 与机器学习模型必须具备版本、数据血缘、评估结果、适用边界和效果监控，不能以黑盒结果替代可解释、可验证的工程判断。

### 6.4 控制策略生命周期

```text
策略假设
仿真推演
风险评估
人工确认
灰度启用
执行监控
readback / 效果确认
异常回退
复盘评估
策略固化
```

控制策略必须默认受限，不得因统一平台建设而弱化现场安全边界。

## 7. 目标达成的核心技术路线

项目采用“数据闭环 + AI + 数字孪生 + 持续改进”的技术路线。

```text
多源数据接入
  -> 数据治理与统一信息模型
  -> 实时 / 批处理 / 历史数据沉淀
  -> 数字孪生与模型表达
  -> AI 诊断、预测、优化与 Agent 交互
  -> 策略推演与多方案评估
  -> 控制策略 / 行动策略 / 管理策略执行
  -> PRC 效果验证
  -> 模型、规则、策略和经验沉淀
```

### 7.1 数据闭环

数据闭环是项目的基础能力。平台必须把现场实时数据、历史数据、事件数据、告警数据、控制数据、运维数据、仿真数据、模型数据和人工反馈纳入统一数据链路。

数据闭环要求：

```text
采得上来
存得可靠
算得清楚
查得一致
用得安全
追得回去
评得出价值
```

### 7.2 数字孪生

数字孪生是数据闭环向决策闭环演进的关键。它把设备、场站、拓扑、测点、模型、约束和控制逻辑统一表达，使系统不仅能记录“发生了什么”，还能分析“为什么发生”“可能如何演化”“不同策略会产生什么影响”。

数字孪生输出不等同于自动决策。其结果应作为运行分析、方案论证、风险评估和人工确认的技术依据。

### 7.3 AI 与机器学习建模

AI 与机器学习用于增强感知、诊断、预测、优化和交互能力。平台应支持：

```text
数据集管理
特征工程
训练任务管理
模型评估
模型注册
模型版本管理
推理服务
模型效果监控
漂移检测
模型回滚
AI Agent 交互
```

机器学习建模能力先归入 Dolphin 能力服务层，按未来独立 MLOps 平台的边界设计。当训练集群、模型注册、特征平台、推理伸缩、模型审批、灰度发布和漂移监控复杂度显著提升时，可再独立拆分。

### 7.4 仿真与优化

仿真与优化用于支撑策略推演、工况分析、控制参数评估、调度协同和资产策略选择。

```text
仿真：回答“在给定模型和工况下会怎样”。
优化：回答“在约束下怎样更好”。
机器学习：回答“从历史和实时数据中能学到什么”。
AI Agent：回答“如何让人更低成本地理解和使用这些能力”。
```

仿真与优化能力先作为 Dolphin 内部能力域，未来当形成独立算力、求解器、实验管理和模型服务体系后，可独立拆分。

### 7.5 AI Agent 与人机协同

AI Agent 是人机协同入口，不是独立决策主体。它应在授权边界内调用数据、模型、指标、仿真、优化和分析服务，为人员提供解释、归纳、检索、对比、提示和辅助推理。

AI Agent 不得默认具备控制下发权限。涉及写入、设点、控制、策略执行和安全边界变更时，必须经过明确授权、审批、审计、fencing、readback 或等价确认机制。

## 8. 决策结果落地形式

PRC 管理、数字孪生推演、AI 分析和优化计算的结果，最终只应落到三类结果上：

```text
运行控制策略
行动策略
持续跟踪与评估
```

### 8.1 运行控制策略

用于短时间尺度内的运行调整，例如功率控制、储能协同、限发响应、波动抑制和调度指令达成。

运行控制策略必须满足：

```text
安全边界明确
授权路径明确
执行范围明确
回退机制明确
审计记录完整
效果可验证
```

### 8.2 行动策略

用于中长期资产管理动作，例如检修、技改、维保、备件、参数调整、模型重训、设备治理和管理措施。

行动策略必须说明：

```text
对象
原因
预期收益
风险影响
成本影响
实施窗口
责任边界
验证指标
```

### 8.3 持续跟踪与评估

用于验证策略是否真正改善资产价值，避免系统停留在“给建议”阶段。

跟踪与评估至少包括：

```text
基线
执行记录
指标变化
风险变化
成本变化
异常副作用
结论复盘
经验沉淀
```

## 9. 建设路线

### 阶段一：数据底座闭环

完成数据接入、消息解耦、原始归档、标准化数据、查询服务和基础治理闭环。

重点是采集可靠性、消息解耦、数据治理、质量码、时间戳、血缘、配置治理、性能容量、异常恢复和安全边界。

### 阶段二：统一信息模型与资产对象体系

建立场站、设备、测点、部件、模型、事件、告警、控制策略、仿真结果、机器学习模型和运维动作的统一标识与关系。

重点是让数据从“按系统分散存储”转为“按资产对象组织”。

### 阶段三：能力服务层

建设数据服务、资产服务、采集管理服务、计算服务、仿真服务、优化服务、机器学习建模服务、检测诊断服务、分析报表服务和控制命令服务。

重点是把数据底座能力封装成可治理、可复用、可审计的服务能力。

### 阶段四：统一应用编排与工作台

建设统一 API、统一认证、统一菜单、统一权限、统一审计、统一错误模型、统一页面风格和统一操作路径。

重点是集中访问路径和统一交互体验，而不是让 Web 直接耦合底层平台。

### 阶段五：数字孪生、AI 与持续优化闭环

建设数字孪生、机器学习、仿真优化、AI Agent 和价值复盘能力。

重点是实现：

```text
模型可管理
策略可推演
风险可解释
收益可验证
经验可沉淀
能力可迭代
```

## 10. 关键原则

### 10.1 价值优先

所有平台能力都必须回答：

```text
它提升了什么资产价值？
降低了什么风险？
减少了什么代价？
支撑了什么决策？
如何验证效果？
```

不能为了做大数据、做微服务、做 AI、做数字孪生而做。

### 10.2 数据先行，但不止于数据

数据是基础，但项目目标不是堆积数据。数据必须进入指标、模型、推演、决策、执行和复盘闭环。

### 10.3 模型辅助，不替代责任

数字孪生、仿真、优化和 AI Agent 提供推演、解释和建议，不替代资产所有者、运行人员和管理人员的责任。

### 10.4 控制链路独立隔离

控制命令、设点、写入和策略执行属于高风险链路，必须独立于普通查询、分析和展示链路。

### 10.5 平台能力产品化

数据底座、能力服务、应用编排和统一工作台必须职责分离。底层能力应通过稳定接口产品化，而不是被某个页面或单一场景硬编码。

### 10.6 持续改进闭环

平台建设与业务运行均采用 PDCA 和 DMAIC 思路，所有改进都应形成基线、措施、验证和固化机制。

## 11. 与需求体系的关系

本文档定义业务目标、价值愿景和建设原则。

正式需求文件负责描述可验收需求、模块承接关系、实现状态、实现证据、验收测试、差距和下一步。本文档不得反向削弱需求文件中的安全、架构、数据治理和测试边界。
