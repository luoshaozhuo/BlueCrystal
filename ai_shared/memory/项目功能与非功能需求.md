# 项目功能与非功能需求

## 一、需求说明

### FR-001 多源异构生产数据接入

- 类型：功能需求
- 来源：项目说明 / 用户指令 / 当前源码
- 来源文件：`ai_shared/memory/project/项目说明.md`、`src/whale/ingest/`、`src/whale/shared/source/`
- 优先级：高
- 需求描述：
  - 平台应支持并网风光储电厂生产运行数据的统一接入，覆盖风机、储能、测风塔、POC 测点、激光雷达及其他现场设备。
  - 接入能力应面向多设备、多协议、多场站、多频率数据源，形成可扩展的生产数据接入底座。
- 验收要点：
  - 至少一条生产级协议链路可从 source 读取数据并进入平台内部状态。
  - 新增生产协议时应具备明确的 client、adapter、配置、测试和运行路径。
  - 不得把测试工具或 simulator 能力直接等同为生产接入能力。
- 备注：
  - source_lab 的 probe、capacity、profile 可作为验证工具，但不是生产 ingest 依赖。

### FR-002 第三方系统数据接入

- 类型：功能需求
- 来源：项目说明
- 来源文件：`ai_shared/memory/project/项目说明.md`
- 优先级：中
- 需求描述：
  - 平台应支持第三方业务系统、分析系统、管理系统、设备厂家平台或外部数据平台的数据接入。
  - 数据形态可包括关系型结构化数据、时序数据、事件数据、统计数据和半结构化数据。
- 验收要点：
  - 提供可配置的数据接入方式。
  - 支持批量同步、周期同步或按需触发。
  - 接入后应纳入统一治理和服务体系。
- 备注：
  - 当前阶段可作为后续扩展能力，不要求与现场高频采集同时完成。

### FR-003 仿真模型与仿真结果数据纳管

- 类型：功能需求
- 来源：项目说明
- 来源文件：`ai_shared/memory/project/项目说明.md`
- 优先级：中
- 需求描述：
  - 平台应支持仿真模型、仿真输入参数、工况配置、计算结果文件和结果数据集的统一登记、存储、关联、检索和服务。
  - 适配单文件、多文件、目录级对象和带元数据的复合数据集。
- 验收要点：
  - 支持模型对象、文件对象、结果对象的元数据登记。
  - 支持对象之间的关联关系。
  - 支持模型与结果的版本追踪。
- 备注：
  - 不要求实时性，重点是可管理、可检索、可追溯。

### FR-004 source 到 cache 的实时状态缓存

- 类型：功能需求
- 来源：当前源码 / 用户指令
- 来源文件：`src/whale/ingest/usecases/source_acquisition_use_case.py`、`src/whale/ingest/adapters/state/redis_source_state_cache.py`
- 优先级：高
- 需求描述：
  - 平台应支持从生产 source client 读取设备状态，并写入状态缓存。
  - 状态缓存应作为实时状态、准实时服务和后续消息发布的基础。
- 验收要点：
  - 支持 polling 采集路径。
  - 支持 subscription 启动时 baseline read。
  - 支持 Redis 等缓存后端。
  - 支持缓存写入异常分类和链路健康状态更新。
- 备注：
  - subscription 运行态断线重连和恢复后重新 baseline 是后续重点。

### FR-005 cache 到 message queue 的状态发布

- 类型：功能需求
- 来源：用户指令 / 当前源码
- 来源文件：`src/whale/ingest/ports/message/message_publisher_port.py`、`src/whale/ingest/adapters/message/`
- 优先级：高
- 需求描述：
  - 平台应支持将 cache 中的设备状态快照或状态变更发布到消息管道。
  - 当前默认目标消息组件为 Kafka，同时保留消息后端可替换边界。
- 验收要点：
  - 提供独立 use case 编排 cache snapshot reader 与 message publisher。
  - 不把 Kafka 发布逻辑塞入 source acquisition use case。
  - 支持消息 payload envelope、schema version、trace id 和基本错误处理。
  - 发布失败不得破坏 source -> cache 主链路。
- 备注：
  - 发布语义可先采用全量快照，后续再演进增量发布。

### FR-006 高频时序数据处理与存储

- 类型：功能需求
- 来源：项目说明
- 来源文件：`ai_shared/memory/project/项目说明.md`
- 优先级：高
- 需求描述：
  - 平台应支撑高频时序数据的持续接入、缓冲、处理、存储与查询。
  - 典型目标是支持单台设备约 10Hz、约 600 字段规模的数据接入，并能扩展到多设备、多场站。
- 验收要点：
  - 提供面向高频数据的吞吐、延迟、容量测试。
  - 存储层支持时序数据写入和时间范围查询。
  - 支持突发流量、短时堆积和补采回灌场景。
- 备注：
  - 状态缓存不等于长期时序存储。

### FR-009 source_lab 本地模拟、探测、容量测试与性能画像

- 类型：功能需求
- 来源：ADR / 当前源码
- 来源文件：`tools/source_lab/`、`ai_shared/adr/`
- 优先级：高
- 需求描述：
  - 项目应提供 source_lab 工具，用于本地 simulator/server、现场 probe、capacity 测试、profile 性能画像和协议行为验证。
  - source_lab 是测试与验证工具层，不是生产 ingest 运行时依赖。
- 验收要点：

  - 支持常用协议的 probe、capacity、profile。
  - 新增协议必须补充 profile 和 capacity 验证。
  - source_lab 不被 ingest 生产路径直接依赖。
- 备注：
  - 工具能力可以支撑生产 client 设计，但不直接等于生产 client 能力。

### FR-010 多协议生产 client 读写能力

- 类型：功能需求
- 来源：用户指令 / ADR / 当前源码
- 来源文件：`src/whale/shared/source/`、`src/whale/ingest/adapters/source/`、`ai_shared/adr/`
- 优先级：高
- 需求描述：
  - 平台应在生产路径中提供多协议 source client，支持读取、订阅和必要的写入/控制能力。
  - 生产 client 应位于 shared/source，并通过 ingest adapter 接入 use case。
- 验收要点：
  - OPC UA 作为第一条生产 client 切片应具备 read/write 路径。
  - 新增协议不能只停留在 source_lab runner 或 simulator 层。
  - 新增协议必须具备生产 adapter、测试和 profile/capacity 验证。
  - 写入能力必须与采集能力分离。
- 备注：
  - 非 OPC UA 协议应逐步建设，不宜一次性虚假标记完成。

- 备注：
  - 写入控制属于高风险能力，应默认关闭真实写入。

### AR-001 Clean Architecture / Port-Adapter 边界

- 类型：架构约束
- 来源：ADR / 当前源码
- 来源文件：`ai_shared/adr/`、`src/whale/ingest/`
- 优先级：高
- 需求描述：
  - 项目应保持 use case、role、port、adapter、runtime、infrastructure 的职责边界。
  - use case 不直接依赖具体基础设施，基础设施通过 adapter 接入 port。
- 验收要点：
  - use case 只编排业务流程。
  - port 只定义抽象契约。
  - adapter 负责连接外部系统。
  - composition 负责依赖装配。
  - 不允许绕过 port 直接调用基础设施。
- 备注：
  - 该约束适用于 source、cache、message、storage 等模块。

### AR-002 source_lab、shared/source、ingest 边界

- 类型：架构约束
- 来源：ADR
- 来源文件：`ai_shared/adr/ADR-20260523-001-source-lab-server-client-ingest-boundary.md`、`ai_shared/adr/ADR-20260523-002-source-lab-task-facade-boundary.md`
- 优先级：高
- 需求描述：
  - source_lab 是测试与验证工具层，shared/source 是生产 source client 层，ingest 是业务用例和生产接入编排层。
  - ingest 不得直接依赖 source_lab。
- 验收要点：
  - simulator、probe、capacity、profile 保留在 source_lab。
  - 生产 client 位于 shared/source。
  - ingest 通过 adapter 依赖 shared/source。
  - source_lab 的 task facade 不进入生产 use case。
- 备注：
  - 这是多协议扩展的核心边界。

### AR-003 采集与写入控制职责分离

### AR-004 生产路径与工具路径分离

- 验收要点：
  - 数据值携带质量码和关键时间戳。
  - 缓存更新具备乱序保护。
  - 支持质量状态和链路状态表达。
  - 后续支持补采、回灌和质量治理规则。
- 备注：
  - 质量治理不能只停留在枚举定义。

### DGR-003 Schema 与配置治理

- 验收要点：

  - 修改配置前读取配置模型和示例配置。
  - 测试结构不得替代生产契约。
- 备注：
  - 这是 AI coding agent 执行任务时的硬约束。

### SCR-001 电力监控系统安全分区与边界防护

- 来源：项目说明
- 来源文件：`ai_shared/memory/project/项目说明.md`

### SCR-002 写入/控制命令安全保护

- 类型：安全合规需求
- 来源：用户指令 / ADR / 当前源码

### SCR-003 数据分类分级与访问控制
