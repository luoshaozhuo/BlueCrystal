# 项目白皮书-总体逻辑设计

## 1. 文件定位

本文档描述 BlueOcean 项目的总体逻辑设计，重点说明系统级组件边界、Whale 数据底座内部逻辑分层、数据链路、技术选型、部署边界和主要设计模式。

本文档不描述业务价值目标，不维护需求跟踪表，不记录实现状态。业务目标、价值愿景、资产全生命周期管理、PRC、数据闭环、AI 与数字孪生的价值逻辑，以《项目白皮书-业务目标与价值愿景.md》为准。可验收需求、实现证据、测试结果和差距，以正式需求文件为准。

本文档粒度为总体设计，不展开函数级、类级和详细实现级设计。

## 2. 总体设计原则

### 2.1 组件并列原则

系统级组件按产品能力域划分，`Whale`、`Turtle`、`Octopus`、`Dolphin`、`Jellyfish`、`Manta` 是并列逻辑组件；`Seahorse` 和 `Starfish` 是实验、样例、仿真与协议验证工具组件。不存在 `Turtle`、`Octopus`、`Dolphin`、`Jellyfish`、`Manta`、`Seahorse` 或 `Starfish` 从属于 `Whale` 的关系。

`PlatformShared` 是全系统公共基础库，不是业务组件、治理控制面、运维执行面或数据底座。它只提供跨组件可复用的中立基础能力。

```text
Manta
  ↓
Jellyfish
  ↓
Dolphin
  ↓
Whale

Turtle  横向提供治理、安全、审计、合规、策略、部署准入、变更控制
Octopus 横向提供运维观测、统一部署编排、自动化巡检、故障恢复

PlatformShared 向所有组件提供公共 SDK / helper / contract
```

### 2.2 数据底座独立原则

`Whale` 是数据底座，负责数据接入、消息解耦、实时处理、原始归档、标准化数据层、批处理、服务查询和数据底座内部公共能力。

`Whale` 不负责统一 Web，不负责业务领域微服务，不负责全局安全治理中心，不负责统一运维编排中心。

### 2.3 治理控制面独立原则

`Turtle` 是治理、安全、审计、合规、策略、部署准入和变更控制面。安全相关能力统一归入 `Turtle`，不得分散到各业务模块中重复实现。

### 2.4 运维执行面独立原则

`Octopus` 是运维观测与统一部署编排执行面。它负责统一部署编排、启停、升级、回滚、巡检、监控、告警、诊断和自动化恢复。

部署执行代码不全部集中到 `Octopus`。单模块部署定义仍随模块保留，`Octopus` 负责统一编排和执行。

### 2.5 公共基础库独立原则

`PlatformShared` 是全系统公共基础库，为 `Whale`、`Turtle`、`Octopus`、`Dolphin`、`Jellyfish`、`Manta` 提供可复用、无业务归属、无运行状态或弱状态的基础代码能力。

`PlatformShared` 可以包含：

```text
crosscutting/observability   轻量 logging、metrics、trace、correlation context
crosscutting/debug           本地诊断上下文、debug snapshot、ring buffer、trace helper
crosscutting/resilience      retry、backoff、timeout、deadline、circuit breaker、error classifier
crosscutting/context         request context、actor context、tenant context、correlation context
contracts/errors             统一错误模型和错误分类
contracts/pagination         分页模型
contracts/result             Result / Outcome 模型
contracts/health             healthz / readyz 基础模型
contracts/api                通用 API envelope、request_id、idempotency key
kernel/time                  UTC 时间、窗口、Clock 抽象
kernel/ids                   resource id、trace id、message id 生成
kernel/serialization         JSON/datetime 编码与解码
kernel/validation            通用校验工具
messaging/envelope           跨组件消息 envelope 基础模型
messaging/correlation        correlation_id、causation_id
messaging/schema_version     schema version 与兼容性辅助
security_primitives/masking  无策略字符串脱敏 helper
security_primitives/hash     checksum、digest、payload hash
security_primitives/redaction 通用字段 redaction helper
```

`PlatformShared` 不得包含：

```text
资产模型、设备模型、测点模型、协议 client、SCADA 参数模型、数据库业务 ORM、Kafka/Pulsar 具体 adapter、TDengine/HDFS 具体 adapter、IAM 策略、审计归集、合规规则、部署编排、运维监控平台、Web 页面模型。
```

依赖规则：

```text
允许：Whale/Turtle/Octopus/Dolphin/Jellyfish/Manta -> PlatformShared
禁止：PlatformShared -> Whale/Turtle/Octopus/Dolphin/Jellyfish/Manta
禁止：Dolphin/Jellyfish/Manta/Turtle/Octopus -> whale.shared
```

### 2.6 架构模式组合原则

系统采用以下模式组合：

```text
Clean Architecture
+ Port-Adapter
+ Pipeline Architecture
+ Event-driven Architecture
+ Layered Data Architecture
```

其中：

- `Clean Architecture` 用于保持领域模型、用例、端口、适配器边界。
- `Port-Adapter` 用于隔离 Kafka/Pulsar、HDFS/Object Storage、TDengine、PostgreSQL、Redis、IAM、SIEM、KMS 等外部系统。
- `Pipeline Architecture` 用于 Flink 流处理作业。
- `Event-driven Architecture` 用于消息管道、异步解耦、回放和故障恢复。
- `Layered Data Architecture` 用于 raw、standardized、warehouse、mart、serving 等数据分层。

## 3. 系统级组件逻辑视图

### 3.1 总体组件

```text
Manta：统一 Web 工作台
  ↓
Jellyfish：应用编排 / BFF / API Gateway
  ↓
Dolphin：能力服务层
  ↓
Whale：数据底座

Turtle：治理 / 安全 / 审计 / 合规 / 策略 / 部署准入 / 变更控制
Octopus：运维观测 / 统一部署编排 / 自动化巡检 / 故障恢复
PlatformShared：全系统公共基础库 / 公共 SDK / helper / contract
Seahorse：样例场站生成器 / replay / 离散仿真 / 外部仿真接入
Starfish：协议 simulator / probe / profile / capacity 工具层
```

### 3.2 组件职责表

| 组件 | 定位 | 核心职责 | 不承担职责 |
|---|---|---|---|
| Whale | 数据底座 | 数据接入、消息、实时处理、原始归档、标准化、批处理、数据服务 | 不做统一 Web，不做业务微服务，不做全局安全治理中心 |
| Dolphin | 能力服务层 | 数据、资产、计算、仿真、优化、机器学习、检测、分析、控制服务 | 不直接连接现场 source，不绕过 Whale 数据治理 |
| Jellyfish | 应用编排层 | API Gateway、BFF、页面模型聚合、路由、限流、错误模型统一 | 不直接访问数据库或现场系统 |
| Manta | 统一 Web 工作台 | 统一入口、统一菜单、统一交互、统一视觉风格 | 不做超级后端，不直连底层中间件 |
| Turtle | 治理控制面 | IAM、安全、审计、合规、策略、部署准入、变更控制 | 不执行部署动作，不做运行监控平台 |
| Octopus | 运维执行面 | 统一部署编排、启停、升级、回滚、巡检、监控、告警、诊断 | 不定义安全治理策略，不替代 Turtle 审批 |
| PlatformShared | 全系统公共基础库 | 公共 SDK、helper、contract、基础上下文、错误模型、可观测工具、韧性工具、诊断工具 | 不承载业务模型、治理策略、运维执行、协议适配和数据库业务 ORM |
| Seahorse | 样例场站与数据生成器 | 生成全平台调试/演示样例数据、ORM seed plan、SignalProfile/SignalProfileItem、连续时序数据、replay、离散仿真和外部仿真接入边界 | 不作为生产采集链路，不直接替代 Dolphin 仿真计算，不写生产数据底座 |
| Starfish | 协议仿真与验证工具层 | 多协议 server simulator、probe、profile、capacity、native runner 管理和协议能力验证 | 不作为 production source client，不进入 ingest 生产 runtime |

## 4. Whale 数据底座逻辑视图

### 4.1 Whale 内部模块

```text
Whale
├── ingest              现场数据接入、状态缓存、消息发布、控制写入边界
├── message_pipeline    消息管道抽象、schema、topic、DLQ、replay、adapter
├── speed_layer         Flink 实时处理应用集合
├── storage             raw/standardized/warehouse/mart/serving_cache 存储层
├── batch_layer         raw -> standardized 的批处理、补跑、重算、血缘
├── serving             数据查询服务层
└── shared              Whale 内部公共基础库，不含 crosscutting
```

### 4.2 Whale 内部数据流

```text
source
  ↓
ingest
  ↓
message_pipeline
  ↓
speed_layer
  ├── raw_archive_writer       -> HDFS / Object Storage 压缩文件
  ├── raw_index_writer         -> TDengine raw_index
  ├── standardized_writer      -> TDengine standardized
  └── serving_cache_updater    -> Redis / 可替换缓存
  ↓
batch_layer
  ↓
storage.standardized
  ↓
storage.warehouse / storage.mart
  ↓
serving
```

### 4.3 Whale 内部模块职责

#### ingest

`ingest` 已作为独立可部署模块建设，保持现有边界不变。

职责：

```text
现场 source 接入
source -> cache
cache -> message
设备写入 / 控制命令边界
运行时调度
配置包导入导出
多节点 lease / fencing
API / worker / scheduler entrypoint
```

不承担：

```text
raw archive 写入
standardized 数据生成
复杂清洗
批处理重算
统一查询服务
```

#### message_pipeline

`message_pipeline` 不重造 Kafka、Pulsar 等消息中间件本体，只做消息管道抽象、配置、schema、topic、DLQ、replay 和 adapter。

职责：

```text
消息 envelope 定义
schema_version 管理
topic / partition / key 策略
MessageSourcePort / MessageSinkPort
Kafka adapter
Pulsar adapter
DLQ
replay
consumer group 配置治理
```

第一阶段适配：

```text
Kafka
Pulsar
```

#### speed_layer

`speed_layer` 是本阶段重点建设对象，本质是 Flink 应用集合。

职责：

```text
从 message_pipeline 消费 ingest 消息
执行轻量实时处理
写 raw_archive
写 raw_index
写 standardized
更新 serving cache
写 DLQ
维护 checkpoint / savepoint / lag 指标
```

边界：

```text
可以做 envelope 校验、schema 校验、字段展开、时间戳规范化、质量码透传、轻量去重。
不做复杂清洗、历史重算、补采回灌、复杂质量规则。
```

#### storage

`storage` 负责数据层的存储抽象、schema、repository、索引、生命周期、manifest 和基础查询能力。

推荐分层：

```text
storage/
├── raw_archive       原始归档层
├── raw_index         原始索引层
├── standardized      标准化数据层
├── warehouse         数仓汇总层
├── mart              数据集市层
└── serving_cache     服务缓存层
```

#### batch_layer

`batch_layer` 负责 raw 到 standardized 的批处理链路。

职责：

```text
按时间窗口读取 raw_archive
执行 processing
写 standardized
记录 job 状态
记录 input_range / output_range
支持失败重试
支持断点续跑
支持补跑和历史重算
记录血缘与规则版本
```

`processing` 不再作为一级架构模块，作为 `batch_layer/processing` 的内部能力存在。

#### serving

`serving` 是 Whale 数据底座对上提供数据查询能力的服务层。

职责：

```text
实时数据查询
历史数据查询
raw 查询
standardized 查询
聚合查询
元数据查询
运行状态查询
```

`serving` 不是 Dolphin。`serving` 只提供数据底座级查询能力；Dolphin 在其上封装业务能力服务。

#### shared

`shared` 是 Whale 内部公共基础库，不是全系统公共库，也不是 Turtle。

保留职责：

```text
source production client
Whale 内部 persistence 基础
Whale 内部 ORM；样例模板和场站 seed 参考数据（reference_data）已迁入 Seahorse；旧路径 src/whale/shared/persistence/template/ 保留为 DeprecationWarning wrapper，仅供迁移期兼容
数据质量枚举
Whale 内部 utils
Whale 内部协议、SCADA、source client 支撑模型；协议仿真工具归 Starfish
```

不再承担：

```text
全局认证
全局鉴权
安全策略中心
审计归集中心
合规证据中心
部署准入中心
crosscutting/debug、observability、resilience 等全系统公共能力
```

`whale.shared.crosscutting` 应删除。原 `debug`、`observability`、`resilience` 迁入 `platform_shared.crosscutting`，由全系统组件复用。

## 5. 数据分层逻辑视图

### 5.1 数据层命名

| 数据层 | 中文名 | 主要存储 | 定位 |
|---|---|---|---|
| raw_archive | 原始归档层 | HDFS / Object Storage + 压缩文件 | 长期原始事实层 |
| raw_index | 原始索引层 | TDengine | 原始数据快速查询索引 |
| standardized | 标准化数据层 | TDengine，可配置后端 | 明细标准层，约等于 DWD |
| warehouse | 数仓汇总层 | 可配置 | 汇总宽表、主题汇总，约等于 DWS |
| mart | 数据集市层 | 可配置 | 面向业务主题的数据集市，约等于 ADS |
| serving_cache | 服务缓存层 | Redis / 可配置 | 最新值、热点数据、短周期查询 |

### 5.2 raw_archive

`raw_archive` 是唯一长期原始事实层。

选型：

```text
HDFS / Object Storage
Parquet / ORC / Avro
ZSTD / Snappy 压缩
```

职责：

```text
保留完整原始消息
保留原始 envelope
保留 topic / partition / offset / message_id / trace_id
支持长期归档
支持回放
支持重算
支持审计追溯
```

### 5.3 raw_index

`raw_index` 是原始数据快速索引层，推荐使用 TDengine。

职责：

```text
按 source_id / device_id / node_key / time 快速查询原始数据
支持排障
支持数据稽核
支持回放定位
支持近期原始曲线查看
```

边界：

```text
raw_index 可以从 raw_archive 或 message replay 重建。
raw_index 不替代 raw_archive。
raw_index 不作为唯一原始事实层。
```

### 5.4 standardized

`standardized` 是标准化数据层，推荐使用 TDengine，但必须通过 port-adapter 保持后端可替换。

职责：

```text
保存标准化后的明细级时序数据
保存统一时间戳
保存统一测点语义
保存单位换算结果
保存质量码和质量细节
保存规则版本和血缘标识
```

数仓语义：

```text
standardized ≈ DWD / 明细标准层
```

### 5.5 warehouse / mart / serving

`warehouse` 用于主题汇总、宽表和面向分析的数据组织。

`mart` 用于面向具体业务主题的数据集市，如设备健康、能量统计、功率预测、储能协同、资产绩效等。

`serving` 用于对上提供统一查询能力，支撑 Dolphin、Jellyfish、Manta 访问数据底座能力。

## 6. Turtle 治理控制面逻辑视图

### 6.1 Turtle 定位

`Turtle` 是与 `Whale` 并列的治理、安全、审计、合规、策略、部署准入和变更控制面。

### 6.2 Turtle 内部模块

```text
Turtle
├── auth                身份、主体、角色、权限、授权
├── security            TLS、证书、密钥、token、安全模型
├── compliance          数据分类、安全区、留存、合规证据
├── audit               审计事件、审计归集、审计查询
├── policy              策略定义、策略版本、策略发布
├── governance          API治理、配置治理、模型治理、数据治理
├── risk                安全风险、控制风险、合规风险
├── deployment_policy   部署准入、环境边界、发布门禁
├── change_control      变更审批、变更记录、回滚约束
├── ports               IAM/SIEM/KMS/CA/PolicyEngine/CMDB 端口
├── adapters            本地/HTTP/DB/外部系统适配器
├── api                 Turtle 服务 API
├── runtime             策略加载、审计归集、健康检查
└── sdk                 其他组件调用 Turtle 的 SDK
```

### 6.3 Turtle 职责边界

Turtle 负责：

```text
谁可以访问
谁可以部署
谁可以控制
数据属于什么安全等级
API 是否允许调用
配置是否允许变更
模型是否允许发布
部署是否满足准入
控制命令是否满足授权和审计要求
所有关键动作是否留痕
```

Turtle 不负责：

```text
执行 docker compose
执行 helm upgrade
执行 kubectl apply
提交 Flink job
启动 TDengine / Kafka / HDFS
采集日志和指标
生成运行 dashboard
实现 retry/backoff/circuit breaker 等运行时工具
实现 logging/metrics/trace SDK
```

Turtle 可治理这些公共能力的策略侧，例如：谁可以开启 debug、哪些字段必须脱敏、哪些事件必须审计、哪些恢复动作需要审批。

## 8. Seahorse 与 Starfish 实验工具逻辑视图

### 8.1 Seahorse 定位

`Seahorse` 是独立的样例场站生成器、数据 generator、replay 与仿真接入组件。它面向平台调试、演示、联调、数字孪生前置验证和测试数据准备，从零生成可用于 BlueOcean 全平台的样例场站世界。

Seahorse 负责：

```text
生成并网型风光储电场样例资产拓扑
生成 Organization / Asset / SCADA / SignalProfile / SignalProfileItem / Endpoint / LD / AcquisitionTask 等 ORM seed plan
生成协议绑定、测点参数、端点参数和采集任务配置
生成连续遥测、遥信、告警、控制回写响应和故障片段数据
支持随机数据、曲线数据、CSV/JSONL replay、离散模型和外部仿真接入的统一策略接口
管理协议参数模板、样例数据规格、GB/T 30966 字段定义和协议查询视图参考数据
生成可供 Starfish 启动协议 server 的 ServerPlan
生成可导入 Whale ingest 的配置包或样例数据库
生成 ScenarioBundle 16 字段场景包作为导出/校验/归档的最小数据单元
```

## 12. 下一阶段最小建设切片

下一阶段目标是将已完成的 ingest 部署到现场，开始采集数据，并可靠落入原始层与标准化数据层，为后续 batch、serving、Dolphin、AI、数字孪生提供数据基础。

```text
ingest
  -> Kafka / Pulsar
  -> Flink speed_layer
      -> raw_archive：HDFS / Object Storage 压缩文件
      -> raw_index：TDengine
      -> standardized：TDengine
```

### 12.2 最小能力

```text

- envelope
- schema_version
- Kafka adapter
- Pulsar adapter
- DLQ
- replay

- raw_archive_writer

- lag / latency / failure metrics

storage：
- raw_archive schema
- raw_index TDengine schema
- standardized TDengine schema
- manifest / lineage / checkpoint repository
```

### 12.3 切换要求

