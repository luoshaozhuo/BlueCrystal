# IEC 60870-5-101 工程说明文档（子站侧重点版）

## 1. 标准概述

IEC 60870-5-101，工程上通常简称 **IEC101**，是电力远动系统中面向串行链路的通信规约。它常用于调度主站与 RTU、变电站远动装置、场站网关之间的遥信、遥测、遥控、遥调、总召、时钟同步等通信。

IEC101 与 IEC104 的 ASDU 语义高度一致。两者都使用 Type ID、COT、Common Address、IOA 和 Information Elements 来描述业务数据。核心区别在于承载链路：

| 协议 | 承载方式 | 典型场景 |
|------|----------|----------|
| IEC101 | 串口、专线、低速链路 | RTU、串口远动、传统调度通道 |
| IEC104 | TCP/IP | 以太网、调度数据网、场站网关 |

IEC101 文档应重点说明串行链路、平衡/非平衡传输、链路地址、轮询、总召和子站侧响应逻辑。

## 2. 角色与通信模式

### 2.1 控制站与被控站

| 角色 | 常用中文 | 典型工程对象 |
|------|----------|--------------|
| **Controlling Station** | 主站 / 控制站 | 调度主站、集控系统、采集主机 |
| **Controlled Station** | 子站 / 被控站 | RTU、远动装置、场站网关 |

IEC101 多用于主站轮询子站。子站侧通常被动响应主站的链路请求、总召、读命令、遥控遥调和时钟同步，同时也可以在允许的链路机制下上送事件数据。

### 2.2 平衡传输与非平衡传输

IEC101 支持两类传输方式：

| 模式 | 含义 | 工程特征 |
|------|------|----------|
| 非平衡传输 | 主站控制链路访问，子站通常只响应 | 常见于传统 RTU 轮询 |
| 平衡传输 | 双方均可启动传输 | 更接近双向链路，但工程使用需双方约定 |

在非平衡模式中，主站通常周期性轮询子站的链路状态、召唤数据或读取事件队列。子站不能像 IEC104 TCP 长连接那样随时主动发送任意数据，而是要受链路访问规则约束。

## 3. 核心概念体系

### 3.1 ASDU

IEC101 的业务数据仍然通过 ASDU 表达：

```text
ASDU
├── Type Identification       1 byte
├── VSQ                       1 byte
├── Cause of Transmission     1 or 2 bytes
├── Common Address of ASDU    1 or 2 bytes
└── Information Object(s)
    ├── Information Object Address  1/2/3 bytes
    └── Information Elements        n bytes，由 Type ID 决定
```

其中：

| 字段 | 含义 |
|------|------|
| `type_id` | ASDU 类型，决定数据编码格式 |
| `cot` | Cause of Transmission，表示本次发送原因 |
| `common_address` | ASDU 公共地址，表示逻辑站或逻辑单元 |
| `ioa` | 信息对象地址 |

### 3.2 Common Address 与 Link Address

IEC101 中需要区分两个地址：

| 地址 | 所在层级 | 含义 |
|------|----------|------|
| Link Address | 链路层 | 串行链路上的站地址，用于链路访问 |
| Common Address of ASDU | 应用层 | ASDU 所属逻辑站或逻辑单元 |

两者可以相同，也可以不同。工程点表应分别配置，不应混用。

示例：

```yaml
link_address: 5
common_address: 1
```

表示串口链路上访问地址为 `5` 的子站，该子站内部 ASDU 公共地址为 `1`。

### 3.3 Type ID

`type_id` 是 ASDU Type Identification，决定数据结构。

常用 Type ID：

| Type ID | 数值 | 含义 | 方向 |
|---------|------|------|------|
| `M_SP_NA_1` | 1 | 单点遥信，不带时间 | monitor |
| `M_SP_TA_1` | 2 | 单点遥信，带 CP24Time2a 时间 | monitor |
| `M_SP_TB_1` | 30 | 单点遥信，带 CP56Time2a 时间 | monitor |
| `M_DP_NA_1` | 3 | 双点遥信，不带时间 | monitor |
| `M_DP_TB_1` | 31 | 双点遥信，带 CP56Time2a 时间 | monitor |
| `M_ME_NA_1` | 9 | 归一化遥测，不带时间 | monitor |
| `M_ME_NB_1` | 11 | 标度化遥测，不带时间 | monitor |
| `M_ME_NC_1` | 13 | 短浮点遥测，不带时间 | monitor |
| `M_ME_TF_1` | 36 | 短浮点遥测，带 CP56Time2a 时间 | monitor |
| `M_IT_NA_1` | 15 | 累计量，不带时间 | monitor |
| `M_IT_TB_1` | 37 | 累计量，带 CP56Time2a 时间 | monitor |
| `M_EI_NA_1` | 70 | 初始化结束 | monitor |
| `C_SC_NA_1` | 45 | 单点遥控命令 | control |
| `C_DC_NA_1` | 46 | 双点遥控命令 | control |
| `C_SE_NA_1` | 48 | 归一化设点命令 | control |
| `C_SE_NB_1` | 49 | 标度化设点命令 | control |
| `C_SE_NC_1` | 50 | 短浮点设点命令 | control |
| `C_IC_NA_1` | 100 | 总召唤命令 | control |
| `C_CI_NA_1` | 101 | 累计量召唤命令 | control |
| `C_RD_NA_1` | 102 | 读命令 | control |
| `C_CS_NA_1` | 103 | 时钟同步命令 | control |

`type_id` 不表示周期、自发或总召。周期、自发和总召响应属于 COT 或子站发布策略。

### 3.4 COT

COT 表示传送原因。

| COT | 含义 |
|-----|------|
| `cyclic` | 周期发送 |
| `background` | 背景扫描 |
| `spontaneous` | 自发发送 |
| `activation` | 激活命令 |
| `activation_confirmation` | 激活确认 |
| `activation_termination` | 激活终止 |
| `interrogated_by_station` | 响应站总召 |
| `interrogated_by_group_1` ~ `interrogated_by_group_16` | 响应第 1~16 组召唤 |

同一个遥测点可以在不同场景下使用同一个 Type ID，但携带不同 COT。

## 4. 链路层帧格式

IEC101 不直接跑在 TCP 上，而是使用串行链路帧。

### 4.1 固定长度帧

固定长度帧常用于链路确认、链路状态请求等。

```text
固定长度帧
├── Start  0x10
├── Control Field
├── Link Address
├── Checksum
└── End    0x16
```

### 4.2 可变长度帧

可变长度帧用于承载 ASDU。

```text
可变长度帧
├── Start  0x68
├── Length L
├── Length L repeated
├── Start  0x68
├── Control Field
├── Link Address
├── ASDU
├── Checksum
└── End    0x16
```

其中业务数据位于 ASDU 内部：

```text
ASDU -> Information Object -> Information Elements
```

### 4.3 IEC101 与 IEC104 帧结构差异

| 项目 | IEC101 | IEC104 |
|------|--------|--------|
| 承载 | 串口链路帧 | TCP APDU |
| 链路控制 | Control Field + Link Address | APCI I/S/U 帧 |
| 可靠性 | 串口链路确认、校验和、轮询 | TCP + APCI 序号确认 |
| 数据语义 | ASDU | ASDU |

IEC101 与 IEC104 的业务数据语义相近，但底层链路机制不同。

## 5. 总召机制

### 5.1 总召定义

总召是主站向子站发送 `C_IC_NA_1`，请求子站返回当前参与总召的信息对象快照。

总召不是订阅，也不是持续发布机制。

典型流程：

```text
主站 -> 子站：C_IC_NA_1，COT=activation，QOI=20
子站 -> 主站：C_IC_NA_1，COT=activation_confirmation
子站 -> 主站：参与总召的遥信/遥测/累计量，COT=interrogated_by_station
子站 -> 主站：C_IC_NA_1，COT=activation_termination
```

### 5.2 总召一次后的发送行为

IEC101 中“召一次，发一次”的理解是正确的，但“发一次”指的是一次总召响应流程，不一定只是一帧。

如果参与总召的数据较多，子站可以分多帧、多 ASDU 返回；如果数据较少，可能一个 ASDU 返回完成。

总召结束后，子站不会因为这次总召而持续发送所有点。后续更新依赖：

| 机制 | 含义 |
|------|------|
| 主站再次总召 | 再次请求全量快照 |
| 组召唤 | 请求某一组信息对象 |
| 周期发送 | 子站按配置周期发送，受链路访问方式约束 |
| 自发发送 | 变化事件发送，受链路访问方式约束 |
| 背景扫描 | 后台扫描发送 |

### 5.3 QOI

| QOI | 含义 |
|-----|------|
| 20 | 站总召 |
| 21~36 | 第 1~16 组召唤 |

参与 QOI=20 或 QOI=21~36 的数据点由子站侧配置决定，不由主站侧点表单方面决定。

## 6. 点表设计

IEC101 点表同样应区分主站侧点表与子站侧点表。

### 6.1 主站侧点表

主站侧点表用于识别和解析子站数据，不决定子站发布策略。

示例：

```yaml
protocol: iec101
role: controlling_station

serial:
  port: COM1
  baudrate: 9600
  bytesize: 8
  parity: even
  stopbits: 1

link:
  mode: unbalanced
  link_address_size: 1
  cot_size: 2
  common_address_size: 2
  ioa_size: 3

stations:
  - link_address: 5
    common_address: 1
    name: wind_farm_rtu

    startup:
      reset_link: true
      general_interrogation:
        enabled: true
        qoi: 20
      clock_sync:
        enabled: true

    points:
      - name: breaker_open
        ioa: 1001
        type_id: M_SP_NA_1
        data_type: single_point
        direction: monitor

      - name: wind_speed
        ioa: 3001
        type_id: M_ME_TF_1
        data_type: float
        direction: monitor
        timestamp: CP56Time2a

      - name: active_power_setpoint
        ioa: 5001
        type_id: C_SE_NC_1
        data_type: float
        direction: control
```

### 6.2 子站侧点表

子站侧点表用于定义本地数据如何映射为 IEC101 信息对象，以及这些信息对象如何响应主站请求或在链路允许时上送。

示例：

```yaml
protocol: iec101
role: controlled_station

serial:
  port: COM1
  baudrate: 9600
  bytesize: 8
  parity: even
  stopbits: 1

link:
  mode: unbalanced
  link_address: 5
  link_address_size: 1
  cot_size: 2
  common_address_size: 2
  ioa_size: 3

stations:
  - common_address: 1
    name: wind_farm_rtu

    points:
      - name: breaker_open
        description: 35kV breaker open status
        source: scada.breaker.open
        ioa: 1001
        type_id: M_SP_NA_1
        data_type: single_point
        direction: monitor

        interrogation:
          enabled: true
          qoi: [20]

        spontaneous:
          enabled: true

        cyclic:
          enabled: false

      - name: wind_speed
        description: average wind speed
        source: turbine_aggregate.wind_speed
        ioa: 3001
        type_id: M_ME_TF_1
        data_type: float
        direction: monitor
        timestamp: CP56Time2a

        interrogation:
          enabled: true
          qoi: [20, 21]

        spontaneous:
          enabled: true
          deadband: 0.2

        cyclic:
          enabled: true
          period_ms: 10000

      - name: active_power
        description: wind farm active power
        source: meter.p_total
        ioa: 3002
        type_id: M_ME_TF_1
        data_type: float
        direction: monitor
        timestamp: CP56Time2a

        interrogation:
          enabled: true
          qoi: [20]

        spontaneous:
          enabled: true
          deadband: 100.0

        cyclic:
          enabled: true
          period_ms: 5000

      - name: active_power_setpoint
        description: active power setpoint command
        target: control.active_power_setpoint
        ioa: 5001
        type_id: C_SE_NC_1
        data_type: float
        direction: control

        command:
          enabled: true
          select_before_operate: true
          timeout_ms: 10000
```

### 6.3 发布策略字段

| 字段 | 含义 |
|------|------|
| `type_id` | ASDU 类型，决定编码格式 |
| `interrogation.enabled` | 总召/组召时是否返回 |
| `interrogation.qoi` | 参与哪些召唤范围 |
| `cyclic.enabled` | 是否周期发送 |
| `cyclic.period_ms` | 周期发送间隔 |
| `spontaneous.enabled` | 是否变化发送 |
| `spontaneous.deadband` | 模拟量变化死区 |
| `command.enabled` | 是否允许遥控/遥调 |

同一个点可以同时参与总召、周期发送和自发发送。三者不是互斥类型。

## 7. 带时间数据

IEC101 支持带时间标签的数据类型。常见时间格式包括 CP24Time2a 与 CP56Time2a。

| 不带时间 | 带短时标 | 带长时标 |
|----------|----------|----------|
| `M_SP_NA_1` | `M_SP_TA_1` | `M_SP_TB_1` |
| `M_DP_NA_1` | `M_DP_TA_1` | `M_DP_TB_1` |
| `M_ME_NC_1` | - | `M_ME_TF_1` |
| `M_IT_NA_1` | `M_IT_TA_1` | `M_IT_TB_1` |

是否带时标由 Type ID 决定，不应对任意 Type ID 随意附加时间字段。

## 8. 子站端 Python 示例代码

以下代码是 IEC101 子站端运行逻辑示例，重点展示点表驱动、总召响应、周期发送、自发发送和遥调处理。具体串口收发和协议编码 API 需要替换为实际 IEC101 库、厂家 SDK 或自研协议栈。

### 8.1 数据结构

```python
from __future__ import annotations

from dataclasses import dataclass, field
from enum import Enum
from time import monotonic, time
from typing import Any, Callable


class Cot(str, Enum):
    CYCLIC = "cyclic"
    SPONTANEOUS = "spontaneous"
    INTERROGATED_BY_STATION = "interrogated_by_station"
    ACTIVATION_CONFIRMATION = "activation_confirmation"
    ACTIVATION_TERMINATION = "activation_termination"


@dataclass(frozen=True)
class InterrogationConfig:
    enabled: bool = False
    qoi: tuple[int, ...] = ()


@dataclass(frozen=True)
class CyclicConfig:
    enabled: bool = False
    period_ms: int | None = None


@dataclass(frozen=True)
class SpontaneousConfig:
    enabled: bool = False
    deadband: float | None = None


@dataclass(frozen=True)
class CommandConfig:
    enabled: bool = False
    select_before_operate: bool = False
    timeout_ms: int = 10000


@dataclass
class Point:
    name: str
    common_address: int
    ioa: int
    type_id: str
    data_type: str
    direction: str
    source: str | None = None
    target: str | None = None
    timestamp: str | None = None
    interrogation: InterrogationConfig = field(default_factory=InterrogationConfig)
    cyclic: CyclicConfig = field(default_factory=CyclicConfig)
    spontaneous: SpontaneousConfig = field(default_factory=SpontaneousConfig)
    command: CommandConfig = field(default_factory=CommandConfig)

    last_sent_value: Any = None
    last_cyclic_send_at: float = 0.0
```

### 8.3 子站运行时

```python
class IEC101ControlledStationRuntime:
    def __init__(
        self,
        *,
        adapter: IEC101SlaveAdapter,
        link_address: int,
        points: list[Point],
        read_source: Callable[[str], Any],
        write_target: Callable[[str, Any], None],
    ) -> None:
        self.adapter = adapter
        self.link_address = link_address
        self.points = points
        self.read_source = read_source
        self.write_target = write_target
        self.monitor_points = [p for p in points if p.direction == "monitor"]
        self.control_points = {(p.common_address, p.ioa): p for p in points if p.direction == "control"}

    def start(self, port: str, baudrate: int = 9600, parity: str = "E") -> None:
        self.adapter.open_serial(port, baudrate, parity)

    def on_general_interrogation(self, ca: int, qoi: int) -> None:
        self.adapter.send_interrogation_confirm(self.link_address, ca, qoi)

        for point in self.monitor_points:
            if point.common_address != ca:
                continue
            if not point.interrogation.enabled:
                continue
            if qoi not in point.interrogation.qoi:
                continue

            value = self.read_source(point.source or point.name)
            self._send_point(point, value, Cot.INTERROGATED_BY_STATION)

        self.adapter.send_interrogation_termination(self.link_address, ca, qoi)

    def on_poll_opportunity(self) -> None:
        """非平衡链路下，主站轮询或链路允许发送时调用。"""
        now = monotonic()
        for point in self.monitor_points:
            value = self.read_source(point.source or point.name)
            self._maybe_send_cyclic(point, value, now)
            self._maybe_send_spontaneous(point, value)

    def on_command(self, ca: int, ioa: int, type_id: str, value: Any) -> None:
        point = self.control_points.get((ca, ioa))
        if point is None or point.type_id != type_id or not point.command.enabled:
            self.adapter.send_command_response(
                link_address=self.link_address,
                ca=ca,
                ioa=ioa,
                type_id=type_id,
                success=False,
            )
            return

        try:
            self.write_target(point.target or point.name, value)
            self.adapter.send_command_response(
                link_address=self.link_address,
                ca=ca,
                ioa=ioa,
                type_id=type_id,
                success=True,
            )
        except Exception:
            self.adapter.send_command_response(
                link_address=self.link_address,
                ca=ca,
                ioa=ioa,
                type_id=type_id,
                success=False,
            )

    def _maybe_send_cyclic(self, point: Point, value: Any, now: float) -> None:
        if not point.cyclic.enabled or point.cyclic.period_ms is None:
            return
        if now - point.last_cyclic_send_at >= point.cyclic.period_ms / 1000.0:
            self._send_point(point, value, Cot.CYCLIC)
            point.last_cyclic_send_at = now

    def _maybe_send_spontaneous(self, point: Point, value: Any) -> None:
        if not point.spontaneous.enabled:
            return
        if point.last_sent_value is None:
            point.last_sent_value = value
            return
        if self._changed(point, point.last_sent_value, value):
            self._send_point(point, value, Cot.SPONTANEOUS)
            point.last_sent_value = value

    def _changed(self, point: Point, old: Any, new: Any) -> bool:
        if isinstance(old, (int, float)) and isinstance(new, (int, float)):
            deadband = point.spontaneous.deadband
            if deadband is not None:
                return abs(float(new) - float(old)) >= deadband
        return old != new

    def _send_point(self, point: Point, value: Any, cot: Cot) -> None:
        ts = time() if point.timestamp == "CP56Time2a" else None
        self.adapter.send_monitor_value(
            link_address=self.link_address,
            ca=point.common_address,
            ioa=point.ioa,
            type_id=point.type_id,
            value=value,
            cot=cot,
            timestamp=ts,
        )
```

### 8.4 IEC101 与 IEC104 子站代码差异

| 项目 | IEC101 子站 | IEC104 子站 |
|------|-------------|-------------|
| 通道 | 串口 | TCP Server |
| 链路地址 | 需要 Link Address | 不使用 IEC101 链路地址 |
| 发送机会 | 受轮询/链路规则影响 | TCP 数据传输启动后可连续发送 |
| 总召语义 | 一次性快照流程 | 一次性快照流程 |
| ASDU 结构 | 基本一致 | 基本一致 |

IEC101 的子站端实现要特别注意链路层状态机。非平衡模式下，即使本地值发生变化，也要遵循主站轮询和链路访问规则，不能简单按 TCP 服务端思路随意发送。

## 9. 工程改进意见

1. 文档必须明确 IEC101 与 IEC104 的 ASDU 语义相近，但链路层完全不同。
2. 点表必须区分 Link Address 与 Common Address。
3. 点表必须区分主站侧点表与子站侧点表。
4. 子站侧点表必须包含总召、周期、自发、命令等发布策略字段。
5. `type_id` 只表示 ASDU 编码类型，不表示发送触发方式。
6. 总召是一次性快照流程，不是订阅。
7. 参与总召的数据由子站侧配置决定，主站点表只能识别和解析。
8. IEC101 非平衡模式下，周期和自发数据也要受链路轮询机制影响。
9. 子站端示例代码应体现 Link Address、总召响应、周期发送、自发发送和遥控遥调处理。

## 10. 安全与运维注意

IEC101 通常运行在串口、专线或隔离链路上，但仍需关注工程安全：

- 串口服务器接入 IP 网络后，应按 IEC104 一样做网络隔离；
- 遥控遥调必须做权限、闭锁、确认和审计；
- 主站轮询周期不宜过短，避免低速链路拥塞；
- 子站事件队列应设置容量、溢出告警和事件补传策略；
- 带时标事件依赖子站时钟，应配置时钟同步；
- 数据质量位不能省略，主站应识别 invalid、old data、blocked 等状态。
