# IEC 60870-5-104 工程说明文档（子站侧重点版）

## 1. 标准概述

IEC 60870-5-104，工程上通常简称 **IEC104**，是电力自动化、调度通信、场站网关和 SCADA 系统中常见的远动通信协议。它在应用层沿用 IEC 60870-5-101 的 ASDU 语义，并将链路承载方式改为 TCP/IP 网络通信。

IEC104 主要用于以下场景：

- 调度主站与变电站、风电场、光伏场站、储能站之间的数据通信；
- 场站网关向调度或集控系统上送遥信、遥测、事件和带时标数据；
- 主站向子站下发遥控、遥调、总召、时钟同步等命令；
- 通过 IP 网络替代传统串口远动通道。

IEC104 的核心不是“按地址读取寄存器”，而是**主站与子站之间交换 ASDU 事件和命令**。主站通常主动建立 TCP 连接，子站通常监听 TCP 端口 `2404`，连接建立后通过 STARTDT 启动数据传输，再进行总召、事件上送、周期上送、遥控遥调等业务流程。

## 2. 角色与工程边界

### 2.1 控制站与被控站

IEC104 中应优先使用以下角色描述：

| 角色 | 常用中文 | 典型工程对象 | 常见 TCP 行为 |
|------|----------|--------------|---------------|
| **Controlling Station** | 主站 / 控制站 | 调度主站、集控系统、数据采集平台 | TCP Client，主动连接 |
| **Controlled Station** | 子站 / 被控站 | RTU、场站网关、升压站监控系统 | TCP Server，监听 2404 |

在多数风电场、光伏场站、储能场站接入场景中，场站侧程序属于：

```text
IEC104 Controlled Station / Server
```

也就是：

```text
主站主动连接场站网关；
场站网关监听 TCP 2404；
场站网关响应 STARTDT、总召、时钟同步、遥控遥调；
场站网关主动上送遥信、遥测、事件和周期数据。
```

因此，面向场站侧开发时，示例代码应重点放在 **子站端 / controlled station / server**，而不是主站端 client。

### 2.2 “Client” 一词的歧义

部分软件库会把“主动建立 TCP 连接的一方”称为 client，把“监听端口的一方”称为 server。这种说法来自 TCP 编程模型。

IEC104 工程文档中更建议按业务角色区分：

| 语境 | Client 可能含义 | 推荐写法 |
|------|----------------|----------|
| TCP 编程 | 主动连接方 | TCP client |
| IEC104 业务 | 主站 / 控制站 | controlling station |
| 场站侧开发 | 子站 / 被控站 | controlled station / server |

如果场站侧程序因网络架构原因主动连接中心服务，也不能简单称为“IEC104 主站”。它可能只是 TCP 连接发起方，但在 IEC104 应用语义上仍承担 controlled station 的业务角色。

## 3. 核心概念体系

### 3.1 APDU、APCI、ASDU

IEC104 报文基本单元是 **APDU**：

```text
APDU = APCI + ASDU
```

更完整地看：

```text
APDU
├── Start Character       1 byte   固定 0x68
├── APDU Length           1 byte   后续长度，不含 Start 和 Length
├── APCI / Control Field  4 bytes  控制域，I/S/U 格式
└── ASDU                  n bytes  应用服务数据单元
    ├── Type Identification       1 byte
    ├── VSQ                       1 byte
    ├── Cause of Transmission     1 or 2 bytes，IEC104 常用 2 bytes
    ├── Common Address of ASDU    1 or 2 bytes，IEC104 常用 2 bytes
    └── Information Object(s)
        ├── Information Object Address  1/2/3 bytes，IEC104 常用 3 bytes
        └── Information Elements        n bytes，由 Type ID 决定
```

真正的数据值不在一个单独叫 `data` 的字段里，而是在：

```text
ASDU -> Information Object -> Information Elements
```

IEC104 常用 APDU 最大长度为 253 字节。该长度包含 4 字节 APCI 和后续 ASDU，不包含最前面的 `0x68` 与 Length 字节。

### 3.2 ASDU 公共地址与 IOA

IEC104 点的定位通常依赖：

```text
Common Address of ASDU + Type ID + IOA
```

| 字段 | 含义 |
|------|------|
| `common_address` / `station` / `ca` | ASDU 公共地址，表示逻辑站、逻辑单元或被控系统分区 |
| `type_id` | ASDU Type Identification，表示数据结构和编码方式 |
| `ioa` | Information Object Address，信息对象地址 |

`common_address` 是协议逻辑地址，不等同于 IP 地址，也不必等同于物理设备。一条 TCP 连接下可以承载多个 Common Address。

例如：

```text
192.168.1.10:2404
  ├── CA=1 风电场总控
  ├── CA=2 升压站
  ├── CA=3 SVG/无功补偿
  └── CA=4 储能系统
```

这表示一个 IEC104 子站服务端代理多个逻辑站或逻辑系统。

### 3.3 Type ID

`type_id` 是 IEC104 ASDU 的 **Type Identification**，决定 ASDU 中 Information Element 的编码格式。

常用 Type ID：

| Type ID | 数值 | 含义 | 方向 |
|---------|------|------|------|
| `M_SP_NA_1` | 1 | 单点遥信，不带时间 | monitor |
| `M_SP_TB_1` | 30 | 单点遥信，带 CP56Time2a 时间 | monitor |
| `M_DP_NA_1` | 3 | 双点遥信，不带时间 | monitor |
| `M_DP_TB_1` | 31 | 双点遥信，带 CP56Time2a 时间 | monitor |
| `M_ME_NA_1` | 9 | 归一化遥测，不带时间 | monitor |
| `M_ME_NB_1` | 11 | 标度化遥测，不带时间 | monitor |
| `M_ME_NC_1` | 13 | 短浮点遥测，不带时间 | monitor |
| `M_ME_TF_1` | 36 | 短浮点遥测，带 CP56Time2a 时间 | monitor |
| `M_IT_NA_1` | 15 | 累计量，不带时间 | monitor |
| `M_IT_TB_1` | 37 | 累计量，带 CP56Time2a 时间 | monitor |
| `M_EI_NA_1` | 70 | 初始化结束 | monitor |
| `C_SC_NA_1` | 45 | 单点遥控命令 | control |
| `C_DC_NA_1` | 46 | 双点遥控命令 | control |
| `C_SE_NA_1` | 48 | 归一化设点命令 | control |
| `C_SE_NB_1` | 49 | 标度化设点命令 | control |
| `C_SE_NC_1` | 50 | 短浮点设点命令 | control |
| `C_IC_NA_1` | 100 | 总召唤命令 | control |
| `C_CI_NA_1` | 101 | 累计量召唤命令 | control |
| `C_RD_NA_1` | 102 | 读命令 | control |
| `C_CS_NA_1` | 103 | 时钟同步命令 | control |

`type_id` 不是 `spontaneous`、`cyclic` 或 `interrogation`。这些属于传送原因或触发策略，最终体现在 COT 中。

### 3.4 COT：Cause of Transmission

COT 表示本次 ASDU 发送的原因。

常见 COT：

| COT | 含义 |
|-----|------|
| `cyclic` | 周期上送 |
| `background` | 背景扫描 |
| `spontaneous` | 自发上送，通常由值变化触发 |
| `activation` | 激活命令 |
| `activation_confirmation` | 激活确认 |
| `activation_termination` | 激活终止 |
| `interrogated_by_station` | 响应站总召 |
| `interrogated_by_group_1` ~ `interrogated_by_group_16` | 响应第 1~16 组召唤 |

同一个监视点可以使用同一个 Type ID，在不同场景下带不同 COT 发出。

例如 `wind_speed`：

```text
总召响应：Type ID = M_ME_TF_1，COT = interrogated_by_station
周期上送：Type ID = M_ME_TF_1，COT = cyclic
变化上送：Type ID = M_ME_TF_1，COT = spontaneous
```

## 4. 协议栈与帧格式

### 4.1 协议栈

| 层级 | 内容 |
|------|------|
| 应用层 | IEC 60870-5-104 ASDU，遥信、遥测、遥控、总召、时钟同步等 |
| 控制层 | APCI，I/S/U 帧、发送序号、接收序号、STARTDT、STOPDT、TESTFR |
| 传输层 | TCP，常用端口 `2404` |
| 网络层 | IP |
| 数据链路/物理层 | Ethernet、光纤、专线、VPN、4G/5G 专网等 |

IEC104 不再使用 IEC101 的串口链路层帧格式，而是通过 TCP 承载 APDU。

### 4.2 I-format 信息帧

I-format 用于承载业务 ASDU，是遥信、遥测、命令响应等数据的主要帧格式。

I-format APCI 控制域共 4 字节：

```text
Byte0-1: 发送序号 N(S)，左移 1 位后小端编码
Byte2-3: 接收序号 N(R)，左移 1 位后小端编码
```

示例：

```text
N(S) = 1
N(R) = 0
N(S) << 1 = 0x0002
N(R) << 1 = 0x0000
```

控制域为：

```text
02 00 00 00
```

一个上送单点遥信的完整信息帧示例：

```text
68 0E 02 00 00 00 01 01 03 00 01 00 E9 03 00 01
│  │  └───────────┘ └─────────────────────────────┘
│  │       APCI                   ASDU
│  │
│  └─ Length = 0x0E = 14 bytes = APCI 4 + ASDU 10
│
└─ Start = 0x68
```

拆解：

```text
68          Start
0E          Length = 14
02 00       Send sequence N(S)=1
00 00       Receive sequence N(R)=0

01          Type ID = 1 = M_SP_NA_1
01          VSQ = 1 个信息对象
03 00       COT = 3 = spontaneous
01 00       Common Address = 1
E9 03 00    IOA = 1001，小端 3 字节
01          SIQ，单点状态 = ON
```

该报文表示：

```text
子站 CA=1 自发上送一个单点遥信：IOA=1001，值为 ON。
```

### 4.3 S-format 与 U-format

| 帧类型 | 用途 |
|--------|------|
| I-format | 承载 ASDU 业务数据，带 N(S)、N(R) |
| S-format | 仅确认接收序号 N(R)，不承载 ASDU |
| U-format | 控制链路状态，如 STARTDT、STOPDT、TESTFR |

常见 U-format：

| 命令 | 含义 |
|------|------|
| `STARTDT_ACT` | 主站请求启动数据传输 |
| `STARTDT_CON` | 子站确认启动数据传输 |
| `STOPDT_ACT` | 请求停止数据传输 |
| `STOPDT_CON` | 确认停止数据传输 |
| `TESTFR_ACT` | 测试帧请求 |
| `TESTFR_CON` | 测试帧确认 |

## 5. 总召与数据上送机制

### 5.1 总召的含义

总召是主站向子站发送 `C_IC_NA_1`，请求子站上送当前参与总召的信息对象快照。

总召不是广播，也不是订阅。它是一次性全量快照请求。

典型流程：

```text
主站 -> 子站：C_IC_NA_1，COT=activation，QOI=20
子站 -> 主站：C_IC_NA_1，COT=activation_confirmation
子站 -> 主站：参与总召的遥信/遥测/累计量，COT=interrogated_by_station
子站 -> 主站：C_IC_NA_1，COT=activation_termination
```

### 5.2 总召一次后的发送行为

总召一次，子站只完成一次总召响应流程。

如果点很多，子站可能连续发送多个 I-format 帧；如果点少，可能一个 ASDU 就发完。无论是一帧还是多帧，都属于本次总召响应。

总召完成后，子站不会因为这次总召而持续不断发送同一批数据。后续持续更新依赖以下机制：

| 机制 | 是否由总召建立 | 含义 |
|------|----------------|------|
| 总召响应 | 是 | 本次总召触发的一轮当前值上送 |
| 自发上送 | 否 | 值变化或状态变化时主动上送 |
| 周期上送 | 否 | 按子站配置的周期主动上送 |
| 背景扫描 | 否 | 按后台扫描策略上送 |
| 周期性总召 | 否 | 主站定时再次发送总召命令 |

### 5.3 QOI 与召唤范围

总召命令中包含 QOI，Qualifier of Interrogation。

| QOI | 含义 |
|-----|------|
| 20 | 站总召，station interrogation |
| 21~36 | 第 1~16 组召唤 |

哪些点参与 QOI=20 或 QOI=21~36，不由主站点表单方面决定，而由子站/RTU/网关侧的信息对象数据库或发布配置决定。

### 5.4 总召、周期、自发三者关系

`type_id`、`interrogation`、`cyclic`、`spontaneous` 应在点表中分开建模。

同一个点可以同时配置：

```yaml
interrogation:
  enabled: true
cyclic:
  enabled: true
spontaneous:
  enabled: true
```

运行效果：

```text
收到总召：上送当前值，COT = interrogated_by_station
周期到达：上送当前值，COT = cyclic
值变化满足条件：上送当前值，COT = spontaneous
```

三者互不排斥。

## 6. 点表设计

IEC104 点表应区分主站侧点表与子站侧点表。

### 6.1 主站侧点表

主站侧点表用于识别、解析、入库和展示子站上送的数据。

主站侧点表通常描述：

```text
我认识哪些 CA/IOA/Type ID；
收到后如何解析；
哪些点是遥信、遥测、遥控、遥调；
连接建立后是否发总召。
```

主站侧点表不能单方面决定子站是否周期上送、是否自发上送、是否参与总召。

示例：

```yaml
protocol: iec104
role: controlling_station

connections:
  - name: wind_farm_gateway
    host: 192.168.1.10
    port: 2404

    startup:
      startdt: true
      general_interrogation:
        enabled: true
        qoi: 20
      clock_sync:
        enabled: true

    stations:
      - common_address: 1
        name: wind_farm

        points:
          - name: breaker_open
            ioa: 1001
            type_id: M_SP_NA_1
            data_type: single_point
            direction: monitor

          - name: wind_speed
            ioa: 3001
            type_id: M_ME_TF_1
            data_type: float
            direction: monitor
            timestamp: CP56Time2a

          - name: active_power_setpoint
            ioa: 5001
            type_id: C_SE_NC_1
            data_type: float
            direction: control
```

### 6.2 子站侧点表

子站侧点表用于定义本地数据如何映射为 IEC104 信息对象，以及这些信息对象如何对外发布。

子站侧点表必须明确：

| 字段 | 含义 |
|------|------|
| `common_address` | ASDU 公共地址 |
| `ioa` | 信息对象地址 |
| `type_id` | ASDU 类型，决定编码格式 |
| `data_type` | 本系统内部数据类型 |
| `direction` | `monitor` 或 `control` |
| `interrogation.enabled` | 是否响应总召/组召 |
| `interrogation.qoi` | 参与哪些召唤范围 |
| `cyclic.enabled` | 是否周期上送 |
| `cyclic.period_ms` | 周期上送间隔 |
| `spontaneous.enabled` | 是否自发上送 |
| `spontaneous.deadband` | 模拟量自发上送死区 |
| `command.enabled` | 是否允许遥控/遥调 |

完整示例：

```yaml
protocol: iec104
role: controlled_station

server:
  bind: 0.0.0.0
  port: 2404

link:
  t1_ms: 15000
  t2_ms: 10000
  t3_ms: 20000
  k: 12
  w: 8

stations:
  - common_address: 1
    name: wind_farm_gateway

    points:
      - name: breaker_open
        description: 35kV breaker open status
        source: scada.breaker.open
        ioa: 1001
        type_id: M_SP_NA_1
        data_type: single_point
        direction: monitor

        interrogation:
          enabled: true
          qoi: [20]

        spontaneous:
          enabled: true

        cyclic:
          enabled: false

      - name: wind_speed
        description: average wind speed
        source: turbine_aggregate.wind_speed
        ioa: 3001
        type_id: M_ME_TF_1
        data_type: float
        direction: monitor
        timestamp: CP56Time2a

        interrogation:
          enabled: true
          qoi: [20, 21]

        spontaneous:
          enabled: true
          deadband: 0.2

        cyclic:
          enabled: true
          period_ms: 5000

      - name: active_power
        description: wind farm active power
        source: meter.p_total
        ioa: 3002
        type_id: M_ME_TF_1
        data_type: float
        direction: monitor
        timestamp: CP56Time2a

        interrogation:
          enabled: true
          qoi: [20]

        spontaneous:
          enabled: true
          deadband: 100.0

        cyclic:
          enabled: true
          period_ms: 2000

      - name: turbine_count_online
        description: number of online turbines
        source: turbine_aggregate.online_count
        ioa: 3010
        type_id: M_ME_NB_1
        data_type: scaled_value
        direction: monitor

        interrogation:
          enabled: true
          qoi: [20]

        spontaneous:
          enabled: false

        cyclic:
          enabled: true
          period_ms: 10000

      - name: active_power_setpoint
        description: active power setpoint command
        target: control.active_power_setpoint
        ioa: 5001
        type_id: C_SE_NC_1
        data_type: float
        direction: control

        command:
          enabled: true
          select_before_operate: true
          timeout_ms: 10000
```

### 6.3 字段含义修正

以下表达应避免：

```yaml
type: cyclic
```

正确做法是：

```yaml
type_id: M_ME_TF_1
cyclic:
  enabled: true
  period_ms: 5000
```

因为 `type_id` 表示编码类型，`cyclic` 表示发布触发策略。

## 7. 带时间数据

IEC104 可以发送带时间标签的数据，但不是任意 ASDU 都附加时间戳，而是选择带时标的 Type ID。

| 不带时间 | 带 CP56Time2a 时间 |
|----------|--------------------|
| `M_SP_NA_1` | `M_SP_TB_1` |
| `M_DP_NA_1` | `M_DP_TB_1` |
| `M_ME_NC_1` | `M_ME_TF_1` |
| `M_IT_NA_1` | `M_IT_TB_1` |

示例：

```yaml
- name: wind_speed
  ioa: 3001
  type_id: M_ME_TF_1
  data_type: float
  timestamp: CP56Time2a
```

`CP56Time2a` 常用于事件顺序记录、遥测时标和调度侧 SOE 分析。

## 8. 子站端 Python 示例代码

以下代码是子站端运行逻辑示例，重点展示 **点表驱动、总召响应、周期上送、自发上送、遥调处理**。具体收发 API 需要替换为实际使用的 IEC104 库或 C 库绑定，例如 lib60870、厂家 SDK 或自研协议栈。

### 8.1 数据结构

```python
from __future__ import annotations

from dataclasses import dataclass, field
from enum import Enum
from time import monotonic, time
from typing import Any, Callable


class Cot(str, Enum):
    CYCLIC = "cyclic"
    SPONTANEOUS = "spontaneous"
    INTERROGATED_BY_STATION = "interrogated_by_station"
    ACTIVATION = "activation"
    ACTIVATION_CONFIRMATION = "activation_confirmation"
    ACTIVATION_TERMINATION = "activation_termination"


@dataclass(frozen=True)
class InterrogationConfig:
    enabled: bool = False
    qoi: tuple[int, ...] = ()


@dataclass(frozen=True)
class CyclicConfig:
    enabled: bool = False
    period_ms: int | None = None


@dataclass(frozen=True)
class SpontaneousConfig:
    enabled: bool = False
    deadband: float | None = None


@dataclass(frozen=True)
class CommandConfig:
    enabled: bool = False
    select_before_operate: bool = False
    timeout_ms: int = 10000


@dataclass
class Point:

    common_address: int
    ioa: int
    type_id: str
    data_type: str
    direction: str
    source: str | None = None
    target: str | None = None
    timestamp: str | None = None
    interrogation: InterrogationConfig = field(default_factory=InterrogationConfig)
    cyclic: CyclicConfig = field(default_factory=CyclicConfig)
    spontaneous: SpontaneousConfig = field(default_factory=SpontaneousConfig)

```

```python
    def send_interrogation_termination(self, ca: int, qoi: int) -> None:

    def send_monitor_value(
        self,
        *,
        ca: int,
        ioa: int,
        type_id: str,
        value: Any,
        cot: Cot,
        timestamp: float | None = None,
    ) -> None:
        raise NotImplementedError

    def send_command_response(self, *, ca: int, ioa: int, type_id: str, success: bool) -> None:
        raise NotImplementedError
```

### 8.3 子站运行时

```python
class IEC104ControlledStationRuntime:
    def __init__(
        self,
        adapter: IEC104ServerAdapter,
        points: list[Point],
        read_source: Callable[[str], Any],
        write_target: Callable[[str, Any], None],
    ) -> None:
        self.adapter = adapter
        self.points = points
        self.read_source = read_source
        self.write_target = write_target
        self.monitor_points = [p for p in points if p.direction == "monitor"]
        self.control_points = {(p.common_address, p.ioa): p for p in points if p.direction == "control"}

    def start(self, host: str = "0.0.0.0", port: int = 2404) -> None:
        self.adapter.listen(host, port)

    def on_startdt_activation(self) -> None:
        self.adapter.send_startdt_confirm()

    def on_general_interrogation(self, ca: int, qoi: int) -> None:
        self.adapter.send_interrogation_confirm(ca, qoi)

        for point in self.monitor_points:
            if point.common_address != ca:
                continue
            if not point.interrogation.enabled:
                continue
            if qoi not in point.interrogation.qoi:
                continue

            value = self.read_source(point.source or point.name)
            self._send_point(point, value, Cot.INTERROGATED_BY_STATION)

        self.adapter.send_interrogation_termination(ca, qoi)

    def tick(self) -> None:
        now = monotonic()
        for point in self.monitor_points:
            value = self.read_source(point.source or point.name)
            self._maybe_send_cyclic(point, value, now)
            self._maybe_send_spontaneous(point, value)

    def on_command(self, ca: int, ioa: int, type_id: str, value: Any) -> None:
        point = self.control_points.get((ca, ioa))
        if point is None or point.type_id != type_id or not point.command.enabled:
            self.adapter.send_command_response(ca=ca, ioa=ioa, type_id=type_id, success=False)
            return

        try:
            self.write_target(point.target or point.name, value)
            self.adapter.send_command_response(ca=ca, ioa=ioa, type_id=type_id, success=True)
        except Exception:
            self.adapter.send_command_response(ca=ca, ioa=ioa, type_id=type_id, success=False)

    def _maybe_send_cyclic(self, point: Point, value: Any, now: float) -> None:
        if not point.cyclic.enabled or point.cyclic.period_ms is None:
            return

        period_s = point.cyclic.period_ms / 1000.0
        if now - point.last_cyclic_send_at >= period_s:
            self._send_point(point, value, Cot.CYCLIC)
            point.last_cyclic_send_at = now

    def _maybe_send_spontaneous(self, point: Point, value: Any) -> None:
        if not point.spontaneous.enabled:
            return

        if point.last_sent_value is None:
            point.last_sent_value = value
            return

        if self._changed(point, old=point.last_sent_value, new=value):
            self._send_point(point, value, Cot.SPONTANEOUS)
            point.last_sent_value = value

    def _changed(self, point: Point, old: Any, new: Any) -> bool:
        if isinstance(old, (int, float)) and isinstance(new, (int, float)):
            deadband = point.spontaneous.deadband
            if deadband is not None:
                return abs(float(new) - float(old)) >= deadband
        return old != new

    def _send_point(self, point: Point, value: Any, cot: Cot) -> None:
        ts = time() if point.timestamp == "CP56Time2a" else None
        self.adapter.send_monitor_value(
            ca=point.common_address,
            ioa=point.ioa,
            type_id=point.type_id,
            value=value,
            cot=cot,
            timestamp=ts,
        )
```

### 8.4 运行逻辑说明

该示例体现以下原则：

```text
type_id 决定编码格式；
interrogation 决定总召时是否返回；
cyclic 决定是否周期上送；
spontaneous 决定是否变化上送；
command 决定是否接受主站控制。
```

同一个点可以在总召、周期、自发三种机制下重复上送，但每次 ASDU 的 COT 不同。

## 9. 重连、初始化与异常处理

### 9.1 主站重连后

子站侧通常不主动发起 TCP 重连，而是监听端口等待主站重新连接。主站重新连接后，应重新 STARTDT，并通常重新总召。

子站侧应做到：

```text
TCP 会话断开后清理会话状态；
保留当前过程数据缓存；
等待主站重新连接；
收到 STARTDT 后允许数据传输；
收到总召后重新按当前值上送快照。
```

### 9.2 子站重启后

子站重启后可发送 `M_EI_NA_1` 初始化结束，提示主站重新同步状态。主站收到初始化结束后，通常应重新总召。

子站侧建议：

```text
启动后加载点表；
建立当前值缓存；
等待主站连接；
STARTDT 后发送初始化结束；
等待主站总召；
按总召配置返回当前快照。
```

### 9.3 数据质量

子站上送时应维护质量位，例如：

| 场景 | 质量建议 |
|------|----------|
| 本地数据有效 | good |
| 数据源中断 | invalid |
| 数据超时 | old data |
| 设备检修或闭锁 | blocked / substituted |

主站侧不能长期认为最后一次值永远有效，应根据链路状态、质量位、时间戳和刷新周期判断数据是否 stale。

## 10. 工程改进意见

基于前面讨论，IEC104 文档和实现应重点修改以下内容：

1. 点表必须显式区分主站侧点表与子站侧点表。
2. 子站侧点表必须包含 `interrogation`、`cyclic`、`spontaneous`、`command` 等发布策略字段。
3. `type_id` 只表示 ASDU 编码类型，不表示 cyclic、spontaneous 或是否参与总召。
4. 总召是一次性快照请求，不是订阅；一次总召可能返回多个 ASDU，但流程结束后不会持续发送同一批数据。
5. 参与总召的数据由子站/RTU/网关侧配置决定，不由主站点表单方面决定。
6. 风电场场站侧开发应以 controlled station / server 为主线。
7. 示例代码应体现子站端对 STARTDT、总召、周期上送、自发上送、遥控遥调的处理。
8. APDU 结构必须完整说明数据位于 ASDU 的 Information Elements 中。
9. I-format 控制域必须给出实际字节例子，避免只写抽象序号。
10. 带时间数据应通过带时标 Type ID 表达，例如 `M_ME_TF_1`，而不是对任意数据随意添加 timestamp 字段。

## 11. 安全注意

IEC104 本身通常不提供现代加密认证能力。工程部署时应避免将 `2404` 端口直接暴露在公网。

建议：

- 使用电力专网、VPN、专线或安全隔离装置；
- 限制主站 IP 白名单；
- 记录遥控遥调审计日志；
- 对命令方向增加权限、闭锁、二次确认与防误逻辑；
- 子站端对异常连接、频繁总召、异常遥控进行限流和告警；
- 对公网或跨域场景采用安全网关或加密隧道。
